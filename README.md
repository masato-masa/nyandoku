# にゃんどく

猫の視野で部屋を埋める論理パズル。美術館（Akari / Light Up）の変種。

- 盤面の一部が**壁**。壁の一部には**数字**が書いてある
- 数字＝その壁の**隣接8マス**にいる猫の数（ちょうど）
- 猫は**数字付きの壁の隣接8マス**にのみ置ける
- 猫の視野＝自分のマス＋隣接8マス＋上下左右の直線（壁で停止）
- **壁以外の全マス**が誰かの視野に入ったらクリア

## 動かす

```bash
npm install
npm run dev      # http://localhost:5173
npm run deploy   # ビルドして GitHub Pages に反映
```

公開版: https://masato-masa.github.io/nyandoku/

`?level=10` のようにクエリを付けると、その面から始められる（動作確認用）。

到達したレベルは `localStorage` の `nyandoku.maxLevel` に保存され、
右上のレベルボタンから 1 〜 最新まで選び直せる（下から上の順に並ぶ）。

## 何をどこに置いているか

```
src/core/puzzle.ts   盤面の生成とソルバ。DOM に触らない純粋ロジック
src/core/game.ts     ゲームの状態遷移。タップ／ドラッグ／取り消し／ヒント
src/core/sfx.ts      効果音。音声ファイルを持たず WebAudio で合成する
src/ui/Board.tsx     盤面の描画と、指の動きの解釈
src/ui/Cat.tsx       猫の画像切り替え（まばたき・表情）
src/ui/icons.tsx     アイコンの SVG
src/ui/styles.css    配色と寸法
src/App.tsx          画面の組み立てと、状態と音の接続
```

中身のパズルを差し替えるときは `core/puzzle.ts` を置き換える。
`ui/` と `sfx.ts` はそのまま使い回せる。

## 猫の素材

`public/cats/` の 4 枚（通常・まばたき・喜び・がっかり）は ChatGPT に描かせた
オリジナル。参考アプリの絵をそのまま持ってきてはいない。

```
assets-src/cats-grid.png   ChatGPT が出した 2x2 グリッド（1254x1254）
  ↓ node scripts/slice-cats.mjs
public/cats/{normal,blink,happy,sad}.png   256x256 / 透過 / 各 25KB 前後
```

グリッドは目分量で並んでいて四等分では位置も大きさも揃わないため、各象限を
アルファの外接矩形で切り直し、4 枚に共通の縮尺をかけてから透明な正方形の
中央に置いている。これをやらないと表情を切り替えた瞬間に猫が伸縮する。

| 場面 | 猫の動き |
|---|---|
| 常時 | 3.6 秒周期のごく浅い呼吸（拡大率 1.035） |
| 考えている間 | 2.6〜6.8 秒の不規則な間隔で 130ms のまばたき。個体ごとに位相をずらす |
| 置いた瞬間 | バネで飛び出す（少し回転しながら） |
| クリア | `happy` に切り替わり、上から順に跳ねる |

## 操作感の作り

- **ドラッグで X を連続塗り** — なぞり始めたマスが空なら塗り、X なら消す。
  指を離すまでその役割は変わらない。
- **経路補間** — 指が速いと `pointermove` が飛ぶので、前回位置から線分を歩いて
  マスを拾う。これが無いと速くなぞったときだけ穴が空く。
- **タップとドラッグの分離は 7px** — 小さいと普通のタップが塗りになり、大きいと
  塗り始めが鈍る。
- **バネアニメーション** — Motion に任せ、イージング時間を手で決めていない。
- **音程が上がる効果音** — WebAudio 合成。音声ファイルを持たない。
- **閉じる途中のダイアログはクリックを通す** — 消えるアニメーションの 0.2 秒間も
  オーバーレイは残っているので、`exit` で `pointer-events` を切っている。
  これが無いと、閉じた直後に押したボタンが無反応になる。
- **レイアウトを絶対に動かさない** — 盤面の行と列を両方 `1fr` で固定し、猫や X は
  `position: absolute` で置く。当初これを怠っていたため、猫を置いた行だけ高さが
  変わり（`139.688px 87.4375px 87.4375px 87.4375px`）、タップのたびに画面全体が
  ずれていた。セルが正方形ですらなかった。

## 見た目の数値の出どころ

meowdoku のブラウザ版を開き、計算済みスタイルから抜き出した実測値。
目分量で似せた数字は入れていない。

| 項目 | 値 |
|---|---|
| 背景 | `#F6F5EF` |
| 盤面 | 白 / 角丸 16px / 内側余白 16px / セル間 6px |
| セル | 角丸 8px |
| 見出し | `Level N` `#735056` 24px / 600 |
| ヘッダー | `1fr auto 1fr` / gap 12px |
| 進捗ピル | 白 / 丸型 / padding 4px 12px 4px 8px / gap 6px / 猫アイコン 24px |
| 進捗の数字 | 18px / 500。現在値 `#22C55E`、総数 `#71717A` |
| 丸ボタン | ヘッダー 32px・フッター 60px、どちらも白 / `0 1px 2px rgb(0 0 0 / .05)` |
| 書体 | Open Sans |

遊びかたは常時表示をやめ、右上の `?` から開くダイアログに入れてある。
ダイアログとレベル一覧は、参考画面のピル（背景 `#FBF1EB` / 文字 `#8A5A5A` /
角丸 12px）をそのまま行の見た目に流用している。

盤面の色だけはこのゲーム独自。見えていない床 `#EBE4DC`、視野に入った床
`#FBD97E`、猫のいる床 `#F7C95C`、壁 `#6F5A5E`。

## 盤面生成でわかったこと

**「猫も視野を遮る」は解に影響しない。** 遮った猫が必ず同じ方向へ視野を出し直す
ので、見えるマスの和集合が遮蔽の有無で一致する。よって計算では遮蔽を無視でき、
各マスの視野を盤面ごとに 1 度だけ求めて使い回せる。

**猫の選び方が、そのまま数字の分布になる。** 当初は「最も多く新しく照らす猫」を
貪欲に選んでいた。これは視野の重複を避けようとするので猫が散らばり、同じ壁の
周りに 2 匹以上が並ばなくなる。結果として数字が 0 と 1 ばかりになっていた。
「1 マス以上新しく照らす候補から無作為に選ぶ」に変えるだけで解決した。

| 8x8・50盤面 | 0 | 1 | 2 | 3 | 4 | 猫 |
|---|---|---|---|---|---|---|
| 最大利得を選ぶ | 231 | 471 | 155 | 12 | 0 | 7.8 |
| 候補から無作為 | 159 | 436 | 300 | 78 | 6 | 10.6 |

**数字の割合は、見た目より生成速度に効く。** 数字は制約でもあるので、減らすと
一意解の探索が枝刈りされず生成時間が跳ね上がる。壁密度よりも遥かに効く。

| 8x8 | 中央値 | 最悪 |
|---|---|---|
| 壁密度 0.43 / 数字 60% | 66ms | 1045ms |
| 壁密度 0.43 / 数字 80% | 2ms | 25ms |

数字の分布は 60% と 80% でほとんど変わらないので、80% を採用している。
「一意になるまで数字を 1 つずつ足す」修復方式も試したが、最悪 556ms で
この単純な設定に負けたため使っていない。

**盤面の上限は 8x8。** 9x9 は最良の設定でも最悪 588ms かかり、「次のレベルへ」を
押した瞬間に固まって見えるため。壁密度は 0.33 → 0.40 → 0.43 と上げている。
