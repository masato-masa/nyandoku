# にゃんどく

meowdoku と同じ Star Battle 系の論理パズル。猫を置く位置を論理だけで決める。

- 各カラー領域に猫は 1 匹
- 各行・各列に猫は 1 匹
- 猫どうしは斜めを含めて隣接できない

## 動かす

```bash
npm install
npm run dev      # http://localhost:5173
npm run deploy   # ビルドして GitHub Pages に反映
```

公開版: https://masato-masa.github.io/nyandoku/

`?level=13` のようにクエリを付けると、その面から始められる（動作確認用）。

## 何をどこに置いているか

```
src/core/puzzle.ts   盤面の生成とソルバ。DOM に触らない純粋ロジック
src/core/game.ts     ゲームの状態遷移。タップ／ドラッグ／取り消し／ヒント
src/core/sfx.ts      効果音。音声ファイルを持たず WebAudio で合成する
src/ui/Board.tsx     盤面の描画と、指の動きの解釈
src/ui/icons.tsx     猫・X・ハートなどの SVG
src/ui/styles.css    配色と寸法
src/App.tsx          画面の組み立てと、状態と音の接続
```

中身のゲームを別のパズルに差し替えるときは `core/puzzle.ts` を置き換える。
`ui/` と `sfx.ts` はそのまま使い回せる。

（150ms / `cubic-bezier(0.4, 0, 0.2, 1)`）のままで、作り込まれていない。

## 猫の素材

`public/cats/` の 4 枚（通常・まばたき・喜び・がっかり）は ChatGPT に描かせた
オリジナル。参考アプリの絵をそのまま持ってきてはいない。

```
assets-src/cats-grid.png   ChatGPT が出した 2x2 グリッド（1254x1254）
  ↓ node scripts/slice-cats.mjs
public/cats/{normal,blink,happy,sad}.png   256x256 / 透過 / 各 25KB 前後
```

生成物のグリッドは目分量で並んでいて四等分では位置も大きさも揃わないため、
各象限をアルファの外接矩形で切り直し、4 枚に共通の縮尺をかけてから透明な
正方形の中央に置いている。これをやらないと表情を切り替えた瞬間に猫が伸縮する。

猫の動きは 4 枚の切り替えと変形の組み合わせ:

| 場面 | 動き |
|---|---|
| 常時 | 3.6 秒周期のごく浅い呼吸（拡大率 1.035） |
| 考えている間 | 2.6〜6.8 秒の不規則な間隔で 130ms のまばたき。個体ごとに位相をずらす |
| 置いた瞬間 | バネで飛び出す（少し回転しながら） |
| クリア | `happy` に切り替わり、上から順に跳ねる |
| 失敗 | `sad` に切り替わり、うなだれて首を振る |

## 操作感の作り

- **ドラッグで X を連続塗り** — なぞり始めたマスが空なら塗り、X なら消す。
  指を離すまでその役割は変わらない（`Board.tsx`）。
- **経路補間** — 指が速いと `pointermove` が飛ぶので、前回位置から線分を
  歩いてマスを拾う。これが無いと速くなぞったときだけ穴が空く。
- **タップとドラッグの分離** — 7px 動いたらドラッグ。小さすぎると普通の
  タップが塗りになり、大きすぎると塗り始めが鈍る。
- **バネアニメーション** — 猫の出現・X の出現・結果表示は Motion のバネ。
  イージング時間を手で決めていない。
- **音程が上がる効果音** — 猫が増えるほどペンタトニックを登る。ドラッグ塗り
  も少しずつ音程が上がる。音声ファイルは持たず WebAudio で合成。
- **触覚** — `navigator.vibrate` を対応端末で使う。
- **レイアウトを絶対に動かさない** — 盤面の行と列を両方 `1fr` で固定し、猫や X は
  `position: absolute` で置く。当初これを怠っていたため、猫を置いた行だけ高さが
  変わり（`139.688px 87.4375px 87.4375px 87.4375px`）、タップのたびに画面全体が
  ずれていた。セルが正方形ですらなかった。

## 盤面生成でわかったこと

領域の作り方が一意解の出やすさを決める。実測値：

| 領域の育て方 | 6x6 で一意解が出る割合 | 8x8 |
|---|---|---|
| 面積を揃えて丸く育てる | 0.0% | 0.0% |
| ランダムに育てる | 0.3% | 0.0% |
| 1 領域を数マス続けて伸ばす（採用） | 17.3% | 実用範囲 |

面積を揃えると領域が解を絞れず、生成器が延々と引き直して固まる。
細長い領域にすると制約が強くなる。ただし細長くするほど面積の偏りが出るので、

- 最大サイズを `n * 1.8` で頭打ちにする（巨大領域を防ぐ）
- 最小サイズ 2 を保証する（1 マス領域は答えがただで見えるのと同じ）

の 2 つで挟んでいる。最小 3 マスを強制すると一意解がほぼ出なくなるため、
2 が限界。盤面の上限を 8x8 にしているのも同じ理由。
